Option Pricing under Rough Volatility (RFSV Model)

The rough fractional stochastic volatility (RFSV) model treats volatility as a much rougher process than standard diffusion models. Instead of a smooth Brownian-driven volatility, the model uses a fractional Brownian motion with a low Hurst exponent, which helps reproduce the steep short-dated skew and persistent volatility clustering observed in equity options.

The pricing framework in rough_vol_with_pseudo_code.pdf combines three ingredients: a risk-neutral log-price process, a fractional Ornstein-Uhlenbeck log-volatility process, and a leverage correlation between the stock and volatility drivers. This yields a Monte Carlo workflow suitable for pricing vanilla European calls under rough volatility dynamics.

$$dY_t=\left(r-\frac{1}{2}\sigma_t^2\right)dt+\sigma_t dW_t^S$$ $$dX_t=\nu dW_t^H-\alpha(X_t-m)dt,\qquad X_t=\log \sigma_t$$ $$d\langle W^S,W\rangle_t=\rho\,dt$$

Here $H$ controls roughness, $\nu$ is the volatility of volatility, $\alpha$ is the mean-reversion speed, $m$ is the long-run log-volatility level, and $\rho$ controls the leverage effect that drives implied-volatility skew.

Pricing algorithm

  1. Build the fractional Brownian motion covariance matrix on the simulation time grid.
  2. Apply a Cholesky decomposition to generate rough volatility paths efficiently.
  3. Simulate correlated volatility and asset-price increments path by path.
  4. Recover terminal asset prices, evaluate the European call payoff, and discount the Monte Carlo average.

Pseudo-code structure

function priceRoughVolOption(params) {
  buildFractionalBrownianCovarianceMatrix(H, T, N_steps);
  L_fBM = choleskyDecomposition(Sigma_fBM);

  for each path:
    Z1, Z2 = generateIndependentGaussianVectors();
    W_H = matrixVectorMultiply(L_fBM, Z1);

    for each time step:
      dW_H = roughIncrement(W_H);
      dW_S = rho * spotDriver(Z1) + sqrt(1 - rho^2) * independentSpotDriver(Z2);
      X = X + nu * dW_H - alpha * (X - m) * dt;
      sigma = exp(X);
      Y = Y + (r - 0.5 * sigma^2) * dt + sigma * dW_S;

    payoff += max(exp(Y) - K, 0);

  return exp(-r * T) * average(payoff);
}

The JavaScript pseudo-code in the PDF uses Float64Array buffers to reduce allocation overhead inside the Monte Carlo loop. That structure is especially useful when rough-path generation and dense linear algebra dominate runtime.
